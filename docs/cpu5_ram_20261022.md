# CPU5 普通 RAM LOAD/STORE 与单事务 owner

2026-10-22，基线 `b5f7a70b76222c2b7f95ec1bf9d28bbaa8f8a743`。本阶段接通 RV32I 普通 RAM 访存、真实 load-use 和唯一 D owner，状态为 **PARTIAL VERIFIED：ALU、整数控制流、普通 RAM 原生接口**。尚未接入 MMIO、CSR、M、Trap/IRQ、Cache/AXI/SoC 或完整十类 Stats；未进行 CPU5 P&R、资源签核或板测。

## 实现与接口

`ENABLE_RAM=0` 保持旧参考配置；独立实验可使用：

```verilog
cpu5_top #(.SKELETON_ONLY(0), .ENABLE_FORWARDING(1),
           .ENABLE_CONTROL_FLOW(1), .ENABLE_RAM(1),
           .BRANCH_RESOLVE_IN_ID(1)) ...;
```

`cpu5_ram_unit.v` 支持 LB/LBU/LH/LHU/LW、SB/SH/SW。用拓展位宽验证普通 RAM 白名单、末字节与对齐；默认范围为 `0x00010000–0x00013fff`。端点保留请求字节地址，返回完整对齐32位字；LOAD 按地址低位选择字节/半字并扩展，STORE 的 data/strobe 同步移位。load rd=x0 仍请求和退休，物理 GPR 不写。

`cpu5_ram_owner.v` 的 IDLE/PRESENTED/ACCEPTED/COMPLETE 保存 seq、PC、instr、地址、size、data/strobe 和 funct3。**issue_fire 在首次呈现边沿分配 owner，d_req_fire 只表示该 owner 的请求已被端口接受**；这澄清历史设计合同§2中“req_fire绑定新owner”的简写。VALID 等待 READY 时请求不撤销、不变形；每个 owner 至多一次请求、一次响应。

EX 仅可提前发起已验证的普通 RAM LOAD，并与该 LOAD 的 EX→MEM 转移同边沿绑定；STORE 只能由最老且获准的 MEM 包首次呈现。已有 held 请求优先，老 STORE 完成前保守阻挡年轻 LOAD，地址不同也不放行。只允许成功、存活 LOAD 完成与新 LOAD 同边沿交接；STORE、error、killed drain 均插入边沿。格式化和响应身份使用旧 owner，不能串到新 EX 地址。

MEM 仍唯一退休，WB 仅写已退休包。真正 LOAD 完成值统一进入 MEM 退休、EX 前递和 ID branch 前递；未就绪最新写者不能退回旧 WB 值。错误 LOAD 响应当拍就压过年轻 ID 重定向。取指错误包即便位形类似 LOAD，也保持 I fault 分类。

外部 flush 用 `flush_ready/flush_fire` 接受年龄切口。已呈现 STORE 不可撤销：覆盖它的 flush 在 PRESENTED/ACCEPTED/COMPLETE 均被拒绝，调用者保持请求，STORE 完成并退休后接受；已退休 WB 继续排空。killed LOAD 保留请求/响应协议，仅丢弃结果，不产生退休、GPR/BP 或 fault。fetch epoch 只用于追溯，不能取消 D owner。

错位、越界和总线错误在正确 MEM 年龄 halt，cause/tval 可观测；**这不是 Trap 入口**。未知/MMIO 地址零 D 请求。STORE 总线错误不承诺回滚，本阶段需 reset 恢复。

# CPU5：条件分支、JAL/JALR 与重定向

2026-10-22，基线 `087fcc654f104eea9b437fb47d7b9dc79e61b9dd`。接入六种条件分支、JAL/JALR，补齐实际整数 branch-use；状态为 **PARTIAL VERIFIED：ALU＋整数控制流子集**。真实 LOAD-use、RAM 事务尚未接入，不能宣布完整3A-2或A01–A16验收。

## 实现与语义

新增 `cpu5_branch_unit.v` 负责 BEQ/BNE/BLT/BGE/BLTU/BGEU、JAL、合法funct3的JALR译码与目标计算。支持B/J/I符号立即数、有符号/无符号比较；JALR先清bit0，再按IALIGN32检查。JAL/JALR写回本条PC+4，rd=x0仍退休但不写。条件分支记录rd=0、value=0、writes=0；not-taken不对未使用的目标报错。

`cpu5_alu_pipeline.v` 和 `cpu5_top.v` 新增 `ENABLE_CONTROL_FLOW=0`，默认保留原参考模式；启用后 `BRANCH_RESOLVE_IN_ID=0/1` 为实际EX/ID解析切换。新配置示例：

```verilog
cpu5_top #(.SKELETON_ONLY(0), .ENABLE_FORWARDING(1),
           .ENABLE_CONTROL_FLOW(1), .BRANCH_RESOLVE_IN_ID(1)) ...;
```

ID模式复用独立hazard选择：真实EX写者命中时等待，不引入EX→ID长组合旁路；就绪MEM/WB可前递，最新未就绪MEM不能被旧WB绕过。EX模式用已接入的EX/MEM、MEM/WB旁路。ID接受时保存解析结果，避免EX持有期间重读变化的RF。普通ALU若携带过期BTB的错误next-PC，也会修正到PC+4。

ID重定向随源的ID转移发生，`kill_ifid=0`；EX重定向随源EX转移发生，`kill_ifid=1`，禁止同边沿年轻IF/ID进入ID/EX。直接使用原 `cpu5_if_adapter` 的接受规则，无额外IF/ID数据寄存拍。IF held请求/在途响应继续按既有协议排空，被重定向取消的响应不能变成有效指令。seq为64位无回卷年龄，fetch epoch只处理IF代际；已退休WB不受年轻冲刷取消。

审查发现并修复一处真实边界：外部flush只杀更年轻指令时，存活分支不能在redirect被屏蔽的同拍被消费。控制流配置在flush当拍暂停ID/EX转移，下一拍重试；按年龄可保留的老MEM退休和已退休WB排空仍可发生。ID/EX两模式均有定向正例和坏RTL拒绝。

MEM仍是唯一架构退休点，更新 `arch_next_pc` 和instret。BP训练只在同一成功退休边沿授权；held MEM不能重复训练。预测关闭时零实际训练、预测计数为零。按原三级计数口径，resolved为branch或JAL，next-PC mismatch包括JALR和普通指令，direction/target error只计branch/JAL的对应条件。not-taken branch训练的target仍是分支目标，普通指令和JALR用清空类型失效旧项。

目标错位或取指错误只作为正确年龄的包停在MEM，零退休、零GPR/BP/redirect副作用。错位cause=0、tval=目标；取指错误cause=1、tval=原PC，adapter以NOP作为故障包的指令占位。合法但未实现的指令继续停住。这些均**不是Trap入口实现**：没有CSR、异常跳转或IRQ。老MEM故障及已知老EX故障压过年轻重定向，已退休WB仍可排空。

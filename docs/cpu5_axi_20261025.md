# CPU5 AXI4-Lite 数据主接口验收

2026-10-25，基线 `88466d9764bd5c36265439720e28bebfd7c684c2`。状态：**PARTIAL VERIFIED：独立 CPU5 AXI4-Lite 数据主接口**。本轮始于 2026-10-24，跨日完成；[接口合同](cpu5_axi_contract_20261024.md)保留原起始文件名。

仅新增一个产品 RTL：`cpu5_axi_lite_top`。它将原 `cpu5_cached_top` 的 D Cache/native 后端连到原 `dmem_axi_lite_bridge`，对外提供19个标准 AXI4-Lite D master 信号；I 端仍是 native 后端。内部层次为 `u_cached`、`u_bridge`，中间描述符为 `native_dmem_*`。所有原 CPU5/CPU3、Cache、桥、RAM、设备和正式 SoC/板顶源码保持原样。

```verilog
cpu5_axi_lite_top #(.SKELETON_ONLY(0), .EXTERNAL_DMEM(1),
    .ENABLE_RAM(1), .ENABLE_FORWARDING(1), .ENABLE_CONTROL_FLOW(1),
    .ENABLE_SYNC_TRAPS(1), .ENABLE_CSR(1), .ENABLE_FENCE(1),
    .ENABLE_ICACHE(1), .ENABLE_DCACHE(1), .ENABLE_MMIO(1)) ...;
// native I、外部 AXI slave 和 CPU 必须共享 reset；按需另开 RV32M/IRQ/设备。
```

完整转发原参数/观察端口；新 guard 要求 EXTERNAL_DMEM=1。CPU5 本地 MMIO 先于 Cache/AXI 截获；沿用原256字节 MMIO overlap guard，没有复制旧三级 SoC 对整个64KiB段的额外限制。核心保存原 byte 地址与 PC；桥接受后只对 AXI 地址整字对齐，已经移位的 wdata/wstrb 不再移位，读响应仍为完整字。

原桥单 outstanding：AW/W 独立有效、分别只握手一次，两个完成后等 B；AR 后等 R。仅 `00` 成功，`01/10/11` 均错误，错误读数据归零。native 最终响应寄存保持，消费后才重新接受请求。Cache、core owner 与 FENCE 因而自然等待完整 AXI refill/写穿透完成，没有新增写缓冲、flush 或 FENCE.I。

正常仿真零 Warning/Error。所有新套件私有 cwd/ini/编译库；程序12份批次波形、192个唯一PASS和实际仿真45份依赖SHA逐项核对。新 wrapper 的参数、native D、19个AXI方向、native I直通与共享复位经独立只读审查，没有阻断项。

**回压口径**：原桥 WAIT_B/WAIT_R 的 READY不依赖CPU最终response-ready。新合法寄存slave和真实RAM实测B/R held均为0；真实core+Cache路径的桥最终native response held也为0。长CPU响应保持由独立桥/Cache BFM测得，不能冒称真实AXI长期回压。AW/W/AR等待与slave B/R延迟分别实测，不用提前于请求接受的响应伪造覆盖。

错误 STORE 的slave可能已写物理RAM后再返回错误，不承诺回滚。共享reset必须扩到外部AXI slave；未共享reset的迟到响应不在保证范围。top无外部flush，killed refill/FENCE等待由合法core flush组合真实Cache/桥验证，真实top程序不冒称IRQ取消已发射LOAD。十类Stats、FENCE.I、DMA一致性、全链II=1与CPU5性能均未据此宣称实现。

# CPU5 基础 FENCE 阶段验收

2026-10-24，基线 `ea03aba50e22ee9ca59c07abe3a7dd4f6f6905c3`。状态：**PARTIAL VERIFIED：基础 FENCE 数据屏障**。设计边界见[本轮合同](cpu5_fence_contract_20261024.md)。

新增默认关闭的 `ENABLE_FENCE`，在 `cpu5_top #(.SKELETON_ONLY(0), .ENABLE_FENCE(1), ...)` 开启。所有 opcode=0x0f / funct3=0 编码采用保守全数据排序，包括 FENCE.TSO、空掩码和保留字段；不读/写保留寄存器，不制造 RAW 依赖，诊断 rd/value=0，next-PC=PC+4。FENCE.I 和其他 funct3 仍精确非法。

MEM 中的 FENCE 等待预边沿 D owner 为空，包含被取消但还未完成的纯 RAM 读。最后响应当拍不能退休 FENCE；其成功退休当拍仍阻止年轻 EX 移动、D 请求及 M 启动。旧 STORE/I/O 按既有不可撤销合同先完成；IRQ、flush、同步 Trap、旧已退休 WB 继续保持原优先级和独立性。无关的 killed DIV 和 IF 事务不成为屏障条件。ID 判定分支模式下，FENCE 错误预测也在 EX 修复。

正常仿真零 Warning/Error。变异包含早退、响应沿旁路、退休沿交接、M 启动、过度等待 DIV、元数据丢失、保留字段产生依赖/写、ID/EX 错预测归属、错误 next-PC，以及解码收窄/错误接受 FENCE.I/忽略功能开关。变异测试实际暴露了缺少年轻 M 启动刺激的覆盖空洞；新增合法定向场景后，漏掉 M 屏障的 RTL 副本已被拒绝。

真实 top 程序没有命中 killed D 等待（等待计数为 0）：top 无外部 flush，已发射 LOAD 原子进入活 MEM 并阻止 IRQ。该等待由核心合法外部 flush 接口定向测试覆盖，没有 force/deposit 或增加 top 测试入口。错误预测 EX 修复通过核心传入预测包验证，顶层 BP 矩阵验证正常真实 IF 执行；不宣称自修改代码或 FENCE.I 支持。

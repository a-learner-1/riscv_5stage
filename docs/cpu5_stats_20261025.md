# CPU5 十类周期 Stats 接入验收

日期：2026-10-25。基线：`102806a554a9ebee497289d4830e59d22bccbdef`（S15）。状态：**PARTIAL VERIFIED: CPU5 ten-class cycle Stats schema4/profile2**。

CPU5 已接入十类注册周期事件、新 schema4/profile2 Stats、独立 C/host 读取接口和真实自读 Stats 的系统顶层。每个活动 CPU 计数边沿恰好归一类，Stats START/STOP 使用 profile_next 对齐 CPU 周期。正式三级 CPU、schema3/profile1 六类 Stats、旧固件和正式发布包保持原样。

## 实现

- 原 `cpu5_alu_pipeline.v` 仅增加独立观察输出和标记块；不向原控制逻辑反馈。`cpu5_top.v` 连接事件，三个 Cache/AXI/D0 壳更新注释；14 个旧直接 core TB 只补显式空输出连接，避免 ModelSim 的 wildcard/缺端口警告。
- 新 `axi_lite_cpu5_stats.v` 保留普通计数和 BP bank，增加十组 64 位周期快照，schema=4；6..9 使用非连续扩展地址。schema4 的 backend-ID offset `0x1c` 明确返回 0/1，旧模块的条件语义不变。
- 新 `cpu5_stats_axi_lite_top.v` 接原 native 同步 IF、CPU5 D0 壳、原 AXI 1x2、AXI RAM 和新 Stats；CPU 自身通过真实有序 AXI 读触发窗口。
- 新 `software/cpu5_stats/` 为显式 schema4/profile2 的头文件与 RV32IM smoke 固件；新 `cpu5_stats_abi.py` host reader 拒绝旧 schema、旧字段数和不闭合窗口。

分类先排除被更老 owner、阶段使能或容量掩盖的原因，再选择 local-MMIO / D-write / D-read / MUL / DIV / load-use / ID / redirect / IF / work。后台 killed M/D 只有真的挡住当前工作才构成等待；零除快路径不以 busy=0 推断没有等待。老 MEM 被 WB 或外部暂停阻塞时，年轻 EX 空槽和 in_ready 不能令 ID/IF 抢占归因。详见[实现合同](cpu5_stats_contract_20261025.md)。

# CPU5 native I/D Cache 接入验收

2026-10-24，基线 `40f92eb6b5da71898f824425a880e7b172c3b85a`。状态：**PARTIAL VERIFIED：独立 CPU5 native Cache 接入**。设计边界见[本轮合同](cpu5_cache_contract_20261024.md)。

新增 `cpu5_cache_adapter` 与 `cpu5_cached_top` 两个 RTL 文件。后者将原 `cpu5_top` 的外部 I/D native 口接入可独立开关的原 I/D Cache，继续暴露 native 后端；原核心、CPU5 top、CPU3、Cache、设备、桥和板顶全部保持原样。本轮未接 AXI/D0/Stats 或正式 SoC。

```verilog
cpu5_cached_top #(.SKELETON_ONLY(0), .ENABLE_RAM(1),
    .ENABLE_ICACHE(1), .ENABLE_DCACHE(1),
    .ENABLE_FORWARDING(1), .ENABLE_CONTROL_FLOW(1),
    .ENABLE_SYNC_TRAPS(1), .ENABLE_CSR(1), .ENABLE_FENCE(1),
    .ENABLE_MMIO(1), .ENABLE_TIMER_DEVICE(1), .ENABLE_SOFTWARE_DEVICE(1)) ...;
// 若开启 CPU IRQ，仍须显式开启相应 IRQ 参数，并连接/清零原始输入。
```

Cache 开关默认 0，关闭通道直接连线、相关计数恒零；开启要求非骨架 CPU，D Cache 另需 RAM。默认各两路×64组×4字，即各 2 KiB。新 wrapper 完整转发原 CPU5 参数/观察端口，内部层次为 `u_cpu`、`u_memory.g_icache.u_cache` / `g_dcache.u_cache`。D Cache 位于原本地 MMIO 路由之后，UART/GPIO/timer/MSIP 不填入 Cache，也不泄漏到后端。

原 Cache 均为阻塞式，D 写穿透、不写分配，无 dirty/write buffer。CPU D owner 直到 Cache 最终响应才释放，原 FENCE 因而等待完整 refill/写穿透；不加新 flush/FENCE.I 机制。killed RAM LOAD 和 stale IF 继续协议排空，不能用 epoch 取消 Cache。后端共享 reset，取消协议与有效位，已完成 RAM 写保留。

正常配置零 Warning/Error。新套件均使用私有 cwd/ini/编译库和实际源码快照；程序按四批各16例运行以避免同时打开过多日志，每批保留完整波形。只读审查逐项核对新 adapter 连接/方向/计数器、wrapper 参数、MMIO 层次、共享复位与 guard，未发现阻断项。

真实 top 没有外部 flush，程序不声称覆盖被 IRQ 取消的已发射 RAM LOAD；killed refill/FENCE 等待由核心合法 flush 接口组合真实 Cache 验证。控制 suite 的 0x2000/未知地址是有序后端替身，真实本地设备零外泄由 cachedtop 程序核验；SB/SH 由 adapter 黄金模型和程序共同覆盖。

程序在一次 terminal JALR 后跳向未预热的冷 ROM 行，关后端新接受并排空已接受事务。最多两条此前已接受的冷行自循环 JAL 可合法退休，明确计入收尾；Cache 前可能还有一笔请求，使用共享 reset 取消。GPR/RAM/计数快照均在 reset 前保存，部分 refill 不安装为完整行。不把不同收尾拍数或退休数冒充统一工作量/性能改善。

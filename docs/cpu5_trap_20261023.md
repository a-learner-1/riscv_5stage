# CPU5 固定向量最小同步 Trap

2026-10-23，基线 `e58148e05c8cd904e8c3fd4a6050ba3d11e7c5e5`。本阶段接通最老 MEM 同步故障裁决、固定向量重定向和故障描述符保存，状态为 **PARTIAL VERIFIED：最小同步 Trap 控制**。软件可访问的 CSR、MRET、IRQ、M、MMIO、Cache/AXI/SoC 和完整十类 Stats 尚未接入；没有 CPU5 STA、资源或板测成绩。

## 行为与边界

默认 `ENABLE_SYNC_TRAPS=0` 保持原 ALU/分支/RAM 实验的 halt 行为；显式启用示例：

```verilog
cpu5_top #(.SKELETON_ONLY(0), .ENABLE_FORWARDING(1),
           .ENABLE_CONTROL_FLOW(1), .ENABLE_RAM(1),
           .ENABLE_SYNC_TRAPS(1), .ENABLE_TRAPS(1),
           .TRAP_VECTOR(32'h00000100)) ...;
```

`TRAP_VECTOR` 是编译期、四字节对齐的固定参数，默认 `0x100`；没有软件 `mtvec`、CSR RMW 或异常返回。`trap_pc/cause/tval` 保存最近事件直至下一事件/reset，`trap_valid` 为事件寄存脉冲；这些是诊断输出，不能冒充完整机器模式 CSR/特权状态。core另提供真实64位 `trap_seq` 及 pre-edge `trap_fire`。

最老、存活 MEM 故障优先于年轻分支/访存和本条退休。`mem_enable=0` 暂停裁决并保留故障；恢复后仅取一次 Trap。Trap 不需要新 WB 槽，已退休老 WB 可以同拍写或保持，不能被年轻故障取消。Trap 边沿不更新 instret、不训练 BP，不产生新 LOAD/STORE，不接收年轻 IFID；清掉源 MEM 与年轻 EX 包，向 IF adapter 发送 kill 型重定向，`arch_next_pc=TRAP_VECTOR`。前端继续依照原 held/stale 合同排空旧请求。

| 故障 | cause | tval |
|---|---:|---|
| 分支/JAL/JALR 实际跳转目标错位 | 0 | 目标地址 |
| 正确取指 owner 的 access error | 1 | 故障 PC |
| 当前 CPU5 子集未支持/非法编码 | 2 | 指令字 |
| EBREAK | 3 | EBREAK 自身 PC |
| LOAD 错位 / 越界或总线错误 | 4 / 5 | 有效数据地址 |
| STORE 错位 / 越界或总线错误 | 6 / 7 | 有效数据地址 |
| M-mode ECALL | 11 | 0 |

ECALL/EBREAK 不退休，PC指向该指令自身。EBREAK的tval选PC，沿用旧工程；[RISC-V机器级规范](https://docs.riscv.org/reference/isa/priv/machine.html)允许此选择。未接入的 M/CSR/MRET 等编码按当前子集的非法指令处理，不能据此声称完整 RV32IM/特权架构已实现。

D 故障源必须通过 `completion_ready` 确认并释放自己的 error completion，不能把同一源组合标 killed，避免反向取消故障判定。Trap 对其他 D owner 只按 source+1 切口取消年轻者；先前被 kill 的纯 LOAD 仍稳定呈现并排空，error 只丢弃。处理程序 ALU 可在其 drain 期间推进，新访存等待唯一 owner。fetch epoch 从不杀 D owner。

STORE 仍只在最老 MEM 首次授权，已呈现事务不可撤销；总线错误在响应归属明确后取一次 Trap并释放 owner。本阶段不承诺已经发生的写入能够回滚。端到端失败STORE端点选择“不改RAM”仅为该测试平台的具体行为。

直接控制包含 MEM 暂停期间缓存的 LOAD/STORE error、老 WB 同拍写/持有、fault自身零退休、年轻STORE首次呈现保护、同拍LOAD error抢年轻JAL、source D ack、held/accepted killed LOAD error排空、handler ALU drain进展、handler新访存等待、reset及64位seq。首轮刺激在ID解析模式误要求已知老EX故障后仍接受年轻包，已修正为保持输入等待Trap；这是测试刺激修正，未放松RTL。

端到端handler在 `0x100` 初始化自身所需寄存器，写RAM签名、LOAD核对并执行正常 `JAL x0,0` 循环。停止时仅关闭I端READY，继续完成已接受响应并排空流水；最终退休/WB与I/D账本全闭合。8批激活避免ModelSim文件句柄上限。核全部8词RAM、7个定义寄存器，另外25个寄存器保持未知；未初始化物理GPR不被oracle的零值替代。handler不返回，未伪造CSR/MRET。

故障注入覆盖 fault PC/cause/tval/向量、seq截32位、MEM使能/WB空间错误门控、丢老WB、故障退休/instret泄漏、年轻SW错误首次发起、遗漏source D ack、handler被旧drain阻塞。每项保留坏源、指定断言、日志和源身份。

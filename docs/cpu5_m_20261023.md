# CPU5 RV32M 与独立 M owner

2026-10-23，基线 `3d2644e248347429610ca46a555c2ed361c6e9ae`。状态：**PARTIAL VERIFIED：RV32M与代际owner**。本轮只接入八种M指令与取消/排空，不接IRQ、MMIO、Cache/AXI/正式SoC或板顶。范围冻结见 [合同](cpu5_m_contract_20261023.md)。

## 实现

```verilog
cpu5_top #(.SKELETON_ONLY(0), .ENABLE_FORWARDING(1),
           .ENABLE_CONTROL_FLOW(1), .ENABLE_RAM(1),
           .ENABLE_SYNC_TRAPS(1), .ENABLE_TRAPS(1), .ENABLE_CSR(1),
           .ENABLE_RV32M(1), .ENABLE_M(1)) ...;
```

新开关 `ENABLE_RV32M=0` 默认保留上一阶段。top历史 `ENABLE_M=1` 自身不启用M；只有新开关打开且历史门使能，才实例化owner。CSR misa随实际接入返回40001100或40000100，软件写合法且忽略；不表示完整ISA合规签核，FENCE等仍待后续。

`cpu5_m_owner.v` 原样复用 `rv32m_unit.v`。issue/start同边沿绑定PC/instr/op/完整64位seq与generation；Fetch epoch仅追溯。start边沿不能消费旧sticky done，下一边沿起才认本owner结果，除零/溢出无需出现busy高或done低。结果可持有到EX允许转级，MEM仍是唯一退休点，数据进入原MEM/WB与前递路径。不同owner不做同拍交接。

首版保守门禁止老MEM访存、CSR/MRET或fault风险未离开时启动年轻M。已经启动的被取消owner继续运算并自动drain/drop一次；后台busy只挡新M，取消后的ALU/CSR和故障入口可继续。新M等旧owner释放再分配新generation。全1代际为耗尽标记，真实64位耗尽由guard拒绝，不能静默回卷。

修复了取指错误包携带M编码时的结果等待死锁：异常包不启动M，绕过EX结果等待进入MEM；不消耗无关旧owner。新增定向场景与移除该旁路的真实RTL变异，后者由专门8边沿进展断言拒绝。

## A′：本次差额由 MUL 等待精确解释

测量副本来自 `fa36f45761ed1de9a9d12fec77d4fed59edc9714`；可综合三级实现仍为已验收的 `347982c30c88095d4a6406bd26c535b7b9f468b5`。使用原 RV32IM/D0/双 Cache/BTB64/O2 workload，各一迭代，50 MHz。START/STOP 以 Stats AR 接受边沿为准，保留所有 START，以最后一次选择窗口；M owner 历史不清零。

| 项目 | smoke | smoke-validation |
|---|---:|---:|
| 周期 | 425,003 | 425,367 |
| 退休指令 | 289,747 | 289,855 |
| MUL start / complete / retire | 9,396 / 9,396 / 9,396 | 9,396 / 9,396 / 9,396 |
| MUL 等待周期 | 28,188 | 28,188 |
| 其他七种 M 操作的 start / wait | 0 / 0 | 0 / 0 |
| work_other − retired | 28,188 | 28,188 |
| 减去 M 等待后的残差 | 0 | 0 |

两个窗口 raw START=2、selected START=1、epoch=raw、STOP=1；均无跨边界 M owner。旧六类、冻结周期和退休数全部闭合，并与第一步 RAW 测量的窗口一致。事件数与主周期分类分别记录，没有再次相加。

每个 MUL 从启动边沿计：单元首次 post-NBA `done` 在 +2，CPU pre-edge `m_complete_x` 在 +3，喂给 instret 的 pre-edge `retire_valid` 在 +4。实际 `m_wait_x` 覆盖启动起的 3 拍。**单元完成延迟不等于 CPU 等待周期。** 当前两个短程窗口的差额确实全由 MUL 解释；没有把这个结果外推成正式 2,000 迭代的逐 opcode 实测分布，也没有预测 CPU5 能净省相同拍数。

额外实跑原 `cpu_top` 的独立退休 oracle：393 个 M owner，覆盖全部八个 opcode，包含 18 个除零/溢出快路径。普通 DIV/REM 的 unit done / CPU complete / retire 为 +32/+33/+34，等待 33 拍；快路径为 +0/+1/+2，等待 1 拍。另有单元定向 14 项及分析器正负自测 84 项。

双种子验收记录进程和两个定向进程均退出 0，8 个原始 CSV 与首次观察字节相同。首次优化保留共 4 条原有 `irq_external` 未连接警告；缓存设计复用时不重发，不能声称警告已修复。首次观察未单独捕获进程码，证据中保留 null；验收复跑捕获为 0。

## B：Cache II=1，当前 CPU 全链最短 II=2

新定向平台分别驱动独立 Cache 和原三级 CPU，通过相同的原 D-Cache→D0 router→同步 BRAM。逐边界记录请求接受、响应消费、地址、数据、owner 和 PC；同拍先处理旧响应 A，再记录新请求 B。

| 测量边界 / 条件 | 接受到响应消费 latency | 相邻接受 II |
|---|---:|---:|
| 独立 Cache，连续命中 LOAD | 1 拍 | 1 拍 |
| 原 CPU→D-Cache，连续命中 LOAD | 1 拍 | 最短 2 拍 |
| D-Cache→D0，快配置补行读 | 1 拍 | 2 拍 |

II 是两次请求接受边沿之差，首笔没有 II；其间可能包含取指、准备数据或背压，不能把所有请求对混成某条指令的固有开销。非法写请求与合法 STORE 的对照桶分开，不能拿非法 strobe 的 II=1 代表真实 SW→LW。

四个 fixture 覆盖 LW→LW、LW→SW、同地址 SW→LW、跨行、双 way/替换、write-through/no-write-allocate、上下游背压、非 RAM 错误响应、未对齐和非法 size/strobe。独立 streaming 快/背压配置各 30 请求，CPU 两配置各 26 请求；返回数据、合法写后新值、请求/响应单在途及退休 PC/rd/value 由独立模型核对。CPU fixture 的故障门是原三级的 `dmem_fault` 及故障指令不退休，不声称验证了 CPU5 Trap/IRQ。

两个 Cache fixture 各观察到 25 次同拍响应＋新请求；其中各 18 对为不同地址且数据不同的 LOAD，证明旧/新 owner 没串。CPU 与 D0 后端没有同拍交接。增加请求等待 2、响应等待 3 后，D0 补行读 II 为 7；消费背压可继续增加 latency。非 RAM 端点为定向 native error surrogate，**不据此报告真实 AXI 链时延或突发吞吐**。

最终 ModelSim 四配置通过，Errors=0、Warnings=0；分析器另从实际 ROM 解码执行，复核退休与请求，并独立模拟 Cache tag/LRU 与内存数据。详细分组、原始事务和测试修订记录见[访存报告](evidence/cpu5_stage05_20261021/memory/README.md)。

## C：最差路径在异常／重定向到 I-Cache 的组合链

直接提取正式 RV32IM performance 位流对应的最终 `.rtr`，报告原始 SHA 为 `e9f50dfa8f1be039b4056225b87cfa36deec7e9682f0fdaa396bcccdf1702dd3`。本次只读解析，没有运行新 STA。

| 角 | Setup Top-3 slack ns | Hold Top-1 ns |
|---|---|---:|
| Slow | +1.269 / +1.860 / +1.961 | +0.026 |
| Fast | +6.810 / +7.158 / +7.215 | +0.022 |

六条 Setup 的共同起点为 `instr_x[26]`，经过 decode/ALU、地址对齐及异常/IRQ 选择、Trap/redirect，抵达 I-Cache 状态／响应逻辑。Slow Top-1 有 21 级，数据延迟 18.524 ns=cell 7.489+route 11.035 ns，布线占 59.571%。这些 Top-3 没经过 M APM 或乘积高半修正，不能把旧构建 WNS 的差值归因于乘法器。

Hold Top-1 为 `wb_rd[4]` 到寄存器堆 LUTRAM 写地址，排名第三为 D-Cache tag 写地址。完整端点、逐弧延迟、clock/CPR/uncertainty、两角 Hold/Recovery/Removal 各三条及 31 份源／约束身份校验见[路由分析](evidence/cpu5_stage05_20261021/timing/timing_review.md)。当前数值仍属于三级 50 MHz 签核，不是 CPU5 Fmax。

## 十类 ABI 与本次边界

[机器设计合同](cpu5_cycle_profile_contract.json)锁定新硬件 schema4、profile2、十位事件；bit0–5 和旧六类 START/STOP 地址保持，bit6–9 为 MUL、DIV/REM、load-use、其他 ID hazard，新增银行位于 0x180/0x1c0 段。年龄优先排除更年轻且被掩蔽的阻塞，再按规格优先级消歧；事件注册延迟与快照 `profile_next` 对齐明确保留实现验收门。

静态核对旧 decoder 的 78 个有效偏移：24 个原周期字不变，新增 16 字全部位于旧保留区且在实际 SoC 0x200 窗口内。12 个坏合同全部拒绝；真实 GCC 预处理验证旧 ABI 通过、新 schema/字段数四组组合被旧 C guard 拒绝。**这里只通过静态设计合同检查**；新 Stats5、固件、十类 one-hot/快照与 CPU5 ready/stall 仍 NOT IMPLEMENTED / NOT RUN。三级 schema3/profile1、旧镜像和位流保持。

本次没有新增 CPU5 可综合 RTL，A01–A16 的 CPU5 实现验收仍 NOT IMPLEMENTED / NOT RUN，尚不宣称完整 SPEC FROZEN。下一步是以这些测量签定接口、D 年龄仲裁、M owner/killed/drain、IRQ/retire 真值表及预期断言，再开展独立 CPU5 骨架和 IF 复用门；本次没有运行 PLL、ILA 或新的硬件成绩。

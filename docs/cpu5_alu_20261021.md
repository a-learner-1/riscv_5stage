# CPU5 3A-1：整数 ALU、GPR 与 MEM 退休

2026-10-21，基线 `46cabef29ca5ae51138996664e8de9a5a0a59a13`。本步完成独立 CPU5 的整数执行子集，仍不替换已上板的三级核。状态为 **PARTIAL VERIFIED：3A-1**，不是完整五级验收。

## 行为与边界

新增 `cpu5_alu_decode.v`、`cpu5_alu_pipeline.v`，复用原 `alu.v`、`regfile.v` 及 IF 包装。支持 21 条：ADD/SUB/AND/OR/XOR/SLL/SRL/SRA/SLT/SLTU、ADDI/ANDI/ORI/XORI/SLLI/SRLI/SRAI/SLTI/SLTIU、LUI/AUIPC。译码检查完整 funct7，M、LOAD/STORE、分支/JAL/JALR、CSR 和其他未接入指令不在本次执行范围。

`cpu5_top` 默认 `SKELETON_ONLY=1` 保留旧 metadata 骨架及测试层级；显式置 0 才进入 ALU 模式。原 IF 的输出寄存器继续直接作为 IF/ID。ID 读取操作数并等待所有 EX/MEM/WB 年长写者离开，包含正在物理写回的 WB 当拍；下一拍才读取新值。这是保守 RAW 等待，尚未接入 3A-2 的前递。

MEM 的当前 `retire_fire` 是唯一退休事件：在同一边沿递增 instret、更新 `arch_next_pc_q`，并把相同 PC/instr/seq/rd/value 注册为退休记录、生成 MEM/WB 包。`retire_valid` 是该事件的边沿后注册观测，不能拿它再延后一拍计数。WB 在后续边沿写入已经退休的 GPR 包，独立于年轻 MEM 等待；WB 背压阻止更多 MEM 退休。手动年龄冲刷只杀未退休包，不能撤销已退休 WB。

x0 读取恒零、禁止物理写；rd=x0 的 ALU 指令照常退休，记录实际 ALU 结果但 writes=0。原 regfile 没有复位清零：测试程序明确初始化 x1..x31，不能声称硬件 reset 会清空 GPR。reset 会清空控制 valid/计数、取消待 WB 的包，取消前已写的寄存器保留。

未支持指令或 IF 故障到达 MEM 后停止推进，不退休、不发出数据请求或外设副作用。这只是本阶段停顿边界，**没有实现 illegal-instruction Trap、异常 CSR 或 IRQ**；合法但尚未实现的指令不能称为架构非法指令。后续恢复只在独立控制测试通过人工 flush 验证，top 尚未连接提交/redirect 控制器。

`cycle_count` 仅为 reset 后活动周期诊断，十类 `perf_cycle_events` 仍为零；尚不能用于完整 CPU5 性能分类。D/M/CSR/Trap/IRQ、分支执行和 BP 提交均未接入，不能运行 CoreMark。

## 实跑结果

| 检查 | 结果 |
|---|---|
| 译码定向测试 | 34,868 组控制检查：25,386 支持、9,482 不支持；另有 21 组手算 ALU 语义；0 error/warning |
| 独立软件 oracle | 从实际机器码解释，91 项已知答案自检；550 条 ALU 指令，21 种每种至少 21 条；包含溢出、符号边界、移位低5位、相邻/间隔 RAW、WAW、双源与 x0 |
| top 端到端 | 无等待与变等待各 550 退休；注入取指错误只退休前3条；45 种未支持/无效编码各只退休前2条。48 场景全部通过，0 error/warning |
| CSV 第二套解释器 | 1193 退休 = 1193 WB 包；1123 次物理 GPR 写 + 70 个 x0 禁写包。逐条 PC/instr/seq/rd/value/writes/nextpc、instret、最终 GPR 与 metrics 全闭合 |
| 控制层8场景 | WB边沿RAW、MEM等待独立排空WB、WB背压与不同owner同拍交接、64位年龄冲刷、跨bit32边界、未支持M停MEM、IF故障停MEM、非空reset，全部通过 |
| 控制账本 | 17 次退休，16 次物理写，另1个已退但待WB包由测试故意reset取消；26次ID接受、2次WB/MEM交接、12拍WB hold、6拍MEM hold |
| 原默认骨架 | 原测试及独立队列通过；29接受 = 21 debug release + 5 kill + 3 reset discard；3个原骨架坏RTL仍被拒绝 |

两条正常 ALU 程序的 RAW 等待分别为 647 / 296 拍；这是不同取指等待模型下的定向测试计数，不是 CoreMark CPI 或前递收益。控制层是人工 enable/flush/seq 驱动，不能替代真实分支或 Trap 的提交仲裁。

新增坏 RTL 注入共8项，全部在原检查门退出1被拒绝：译码接受M、SUB误作ADD、I立即数错误零扩展、允许写x0；管线忽略WB相关、用延迟retire_valid计数、WB错误受MEM使能阻断、flush丢弃已退休WB。分析器另拒绝3种坏CSV：WB值错、删除WB、退休instret错。坏样本单独保存，未覆盖正常证据。

首跑 top TB 曾在 PC0 接收 X：ROM 数组隐藏在函数全局读取中，首地址保持0时 `$readmemh` 后没有触发刷新。改为显式组合数组读取后通过，CPU RTL未因此改动；初始失败日志及原TB保留。控制脚本首次把正常 `$finish` 当作失败退出，改用明确 test_pass 门；综合验证脚本也修正过成功标记拼写。所有最终正例都退出0。

完整 A01–A16 仍 NOT RUN。本步仅验证整数运算、GPR/x0、退休/写回、保守 RAW 和人工冲刷的适用子集；访存、M、CSR、Trap/IRQ、真实分支及全部 side-effect owner 验收需在各阶段完成。

## 复跑与证据

在工程根目录，用 Python 3 与 ModelSim 10.6e：

```powershell
python -B tools/verify_cpu5_alu.py
python -B tools/verify_cpu5_scaffold.py
```

第一个命令依次执行三份 `run_cpu5_alu_*.do`、生成机器码与期望值、独立分析48份CSV并运行3项CSV拒绝自检；结果在 `build/cpu5_s2_verification/verification.json`。第二个验证默认 metadata 模式及原3个骨架坏RTL。8项新增坏RTL的独立进程、原始坏源、DO、trace、退出码均在冻结证据中。

[长期证据](evidence/cpu5_alu_20261021/README.md)包含原始日志、向量、CSV、压缩波形、负例与 SHA。源归档及保护快照在本机 `build/verification/cpu5_alu_20261021/`。证据记录实测字节SHA；源清单另列规范LF SHA，以核对Git换行规范化后的blob。

原845份已有文件中，仅按本步范围修改 `rtl/cpu5_top.v`；其余844份逐字节保护，包含旧三级产品、用户未提交文件、正式固件、位流与P&R报告。本轮没有P&R、资源/频率测量、板测或性能提升结论。

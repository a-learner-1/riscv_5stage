# 机器外部／软件中断（代码准备，验证待完成）

**更新：2026-10-10。** 本步骤在既有机器定时器中断基础上增加单路机器外部中断和软件中断，并准备独立 `machine_irq_board` 自检。按照用户“暂时不验证”的安排，只修改源代码、构建入口、自检平台和文档，未运行 GCC、ModelSim、PDS 或上板。新功能、默认关闭的兼容性、资源和时序均待验证。

## CPU 接口

`cpu_top` 和 `soc_axi_lite_top` 新增默认关闭的 `ENABLE_EXTERNAL_IRQ=0`、`ENABLE_SOFTWARE_IRQ=0`，启用时要求 `ENABLE_TRAPS=1`。外部请求使用新增输入 `irq_external`，在 CPU 内由两级触发器同步。预测器和 Cache 开关独立于中断开关。

外部输入为高有效电平：外设维持请求，ISR 在外设清除来源，CPU 不在进入中断时自动清除请求。将来接 CNN 时，需要队友提供保持到软件确认的完成标志／中断源；直接输入短脉冲可能漏采，跨时钟源需要保证请求持续时间或采用握手。本接口仅同步电平，不实现脉冲捕获协议。

软件中断使用 CPU 本地、不可缓存的 `0x20000050`：

| 访问 | 行为 |
| --- | --- |
| 对齐 `LW` | bit0 返回 MSIP，高 31 位为零 |
| 对齐 `SW` | 将写入数据 bit0 作为新的 MSIP；写 1 挂起，写 0 清除 |
| 字节／半字或未对齐访问 | 按已有非法访存路径处理，无寄存器写入副作用 |
| 软件中断关闭 | 此地址不映射，不用于其他 RAM 访问 |

复位清除 MSIP 和外部同步状态。软件寄存器在请求成功接受时更新一次；访存等待不会重复更新。

## CSR 与优先级

| 中断源 | `mie` 使能位 | `mip` 挂起位 | `mcause` |
| --- | --- | --- | --- |
| 外部 | MEIE，bit11 | MEIP，bit11 | `0x8000000b` |
| 软件 | MSIE，bit3 | MSIP，bit3 | `0x80000003` |
| 定时器 | MTIE，bit7 | MTIP，bit7 | `0x80000007` |

任一机器中断源开启后，`mie`／`mip` 可访问；未开启源对应位读零。`mie` 仅保留实际启用源的使能位，`mip` 反映源状态，CSR 写入不改变挂起源。全局使能仍由 `mstatus.MIE` 控制。

多个已使能请求同时挂起时，优先级为 **机器外部 → 机器软件 → 机器定时器**。该优先级与 MSIP／MEIP 来源规则依据 [RISC-V 机器模式规范](https://docs.riscv.org/reference/isa/priv/machine.html)。同步异常继续优先于异步中断；处理程序复用现有 direct `mtvec`、`mepc`、`mcause`、`mtval` 和 `MRET`。

已经开始的访存描述符必须排空，包括请求背压和响应等待。中断入口不能重放 STORE／MMIO。中断记录恢复地址，MRET 重新执行尚未完成的指令；IRQ 进入时不把 `mepc` 加 4。中断与同步异常共享重定向路径，丢弃旧取指响应，清除年轻指令；被抢占的指令不用于 BTB 训练。

## 独立外部中断演示源

新增 `axi_lite_irq_demo` 是板级自检外设，使用 `0x30000000` 的独立地址窗口。它用于确认总线写入产生的外部电平请求能到达 CPU，不代表 CNN 的真实寄存器协议，也不是 PLIC。

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| `0x00` | RO | ID `0x49525131` |
| `0x04` | RO | bit0 为挂起电平 |
| `0x08` | WO | 写入 bit0=1 置挂起；bit0=0 无操作 |
| `0x0c` | WO | 写入 bit0=1 清挂起；bit0=0 无操作 |
| `0x10` | RO | 成功执行置位命令的次数，32 位 |
| `0x14` | RO | 成功执行清除命令的次数，32 位 |

只接受完整字写入（`WSTRB=0xf`）；写只读、读只写、未映射、未对齐或部分字写返回 `SLVERR`，不改变挂起与计数。AW／W 独立接受，成功写入仅产生一次副作用；B／R 背压时响应保持。复位清除挂起、计数和在途事务。

## 专用板级版本

`machine_irq_board_top` 使用 50 MHz、115200／8N1、ROM 32 KiB、AXI RAM 16 KiB，显式开启同步异常及三类机器中断。独立自检默认关闭 I/D Cache 和 BTB，以便确认中断逻辑。板级接口沿用 UART、LED 和按键约束，演示中断源在 FPGA 内部，不需要增加物理接线。

固件安装保存全部通用寄存器的中断入口，自动产生外部、软件和定时器请求，检查单独使能、屏蔽挂起与同时挂起时的优先顺序。预期 8 次处理顺序为 `11,3,7,11,3,11,3,7`，计数为外部 3、软件 3、定时器 2；同时检查前台 2048 次运算的恢复与校验和 `0x569ea33c`。意外异常输出 FAIL 并停止，不能跳回启动代码清除失败记录。

成功时预期串口完整输出 `MACHINE IRQ PASS\r\n`（18 字节），LED bit1 常亮、bit0 心跳；KEY1 复位后重跑。失败时预期 `MACHINE IRQ FAIL XXXXXXXX\r\n`（27 字节），LED bit2 常亮。上述均为待验证现象，当前没有配套新镜像或位流。

## 恢复验证后的命令

先回归既有 CPU、CSR／trap、定时器、取指／数据握手、Cache 和 BTB，确认默认关闭模式的兼容性；再执行新增定向自检。

在 ModelSim 的仓库根目录运行不依赖新 GCC 产物的源级定向自检：

```tcl
cd D:/FPGA/riscv_3stage
do run_machine_irq.do
```

之后在 Git Bash 构建独立硬件／快速心跳仿真镜像：

```bash
cd /d/FPGA/riscv_3stage
cmd.exe //c build_machine_irq_board.bat
```

构建器须检查 ISA、ROM／RAM 容量、栈空间、源码及镜像哈希。硬件与仿真指令相同，仅 RAM 初始化心跳周期不同。本步修改了公共 CPU／SoC 源码，既有带源码哈希保护的固件报告可能过期，恢复验证时需要重新构建对应版本。板级仿真入口先检查报告与当前源码、镜像一致：

```tcl
do run_machine_irq_board.do
```

功能检查完成后，在 Git Bash 生成独立 PDS 工程与候选位流：

```bash
cmd.exe //c build_pds_board.bat --variant machine_irq_board --firmware machine_irq_board --stage bitstream
```

预期位流路径为 `build/pds_machine_irq_board/generate_bitstream/board_top.sbit`。通过资源、布局布线和 50 MHz 时序检查后，由用户手动下载，在 SSCOM 保存完整日志，并检查 LED、KEY1 重启行为。本轮没有执行任何上述命令。

新增仿真源码包含 11 个 CPU 定向场景、独立 AXI 演示源测试，以及正常完成、ISR 内按键复位、破坏初始化校验后 FAIL／复位恢复三个板级场景。板级平台保留 50 MHz／115200 的实际串口时序，复位等待在仿真中缩短到 16 周期；PDS 顶层仍固定为 50000 周期。每次启动按链接脚本的 `tohost` 符号检查 main 成功清零后才允许中断和完成写入。上述检查均是已编写、未执行的测试内容。

## 实现边界

本步骤扩展单 hart 的三类 M 模式中断源，仍保留既有最小机器模式异常环境。当前不包含 PLIC／多个外设的 claim-complete、向量 `mtvec`、嵌套中断、S/U 模式或完整特权架构验收。CNN 寄存器地址、共享内存与 DMA Cache 一致性需要另行约定；增加中断输入不能替代这些工作。既有历史板级 PASS 和 CoreMark 成绩属于当时版本，不能作为本次修改后的验收证据。
